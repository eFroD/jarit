# JarIt v1.2.0

This release makes extraction asynchronous with live progress and a personal history, encrypts stored integration credentials, speaks five languages, and keeps yt-dlp current without updating at container start.

## ⚠️ Breaking changes – read before upgrading

### 1. `JARIT_ENCRYPTION_KEY` is now required

Integration credentials (e.g. users' Mealie API keys) are now encrypted in the database. The backend **does not start** without a valid key.

Before you upgrade:

1. Generate a key:

   ```bash
   docker run --rm python:3.13-slim sh -c "pip -q install cryptography && python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'"
   ```

2. Add it to your `.env`:

   ```bash
   JARIT_ENCRYPTION_KEY=<your generated key>
   ```

3. If you use your own compose file, pass the variable to the backend container (`JARIT_ENCRYPTION_KEY=${JARIT_ENCRYPTION_KEY}`), as in the provided `docker-compose.yml`.

On the first start, existing plain-text credentials are encrypted automatically; users do not need to do anything.

**Back up the key together with your database.** JarIt does not re-encrypt data: if the key is lost or changed, all stored credentials become unreadable, and users have to enter their Mealie API key again. If the key is missing or invalid, the backend log prints a freshly generated key and the exact `.env` line to use.

### 2. Back up your database – migrations now run automatically

The schema is now managed with Alembic, and migrations run at backend start. Existing installations are detected and brought under migration control without data loss. This release adds the tables and columns for extraction jobs and user languages. **Back up your database before upgrading.**

### 3. Run the backend as a single process

Extractions now run as background jobs inside the backend process. Do not start uvicorn with `--workers` greater than 1 (the provided compose files already run one process). A restart marks running and waiting extractions as interrupted; users can retry them with one click.

### 4. API changes (only relevant if you call the API directly)

- `POST /api/v1/recipes/extract-recipe` and `POST /api/v1/integrations/upload-mealie` are **removed**. Use the extraction jobs API instead:
  - `POST /api/v1/extraction-jobs` returns `202` with a job at once
  - `GET /api/v1/extraction-jobs/{id}` for status and result
  - `POST /api/v1/extraction-jobs/{id}/upload-mealie` to upload
- `target_language` now takes a language code: `en`, `de`, `es`, `fr` or `it`. Values like `"english"` are rejected with `422`. If it is omitted, the user's own language is used.
- Error responses contain a stable `code` next to `detail`, e.g. `{"detail": "Only failed extractions can be retried", "code": "JOB_NOT_RETRYABLE"}`.

## ✨ New

### Background extraction with progress
- Submitting a video URL returns immediately; the extraction runs in the background.
- A progress page shows each step (fetching the description, transcribing audio if needed, extracting the recipe) and the running time. You can leave and come back at any time.
- Failures show an understandable reason (e.g. "Video unreachable", "No recipe found in this video") and a **Try again** button. Technical details only go to the log.
- `JARIT_MAX_CONCURRENT_EXTRACTIONS` (default `2`) limits how many extractions run at once; further jobs wait their turn. Extractions that take longer than 10 minutes are stopped.

### Extraction history
- **History** lists all your extractions, newest first, with their status and whether the recipe is already in Mealie.
- Reopen, edit and save recipes, upload them (again) to Mealie, retry failed extractions or delete entries.
- Each user only sees their own extractions, admins included.

### Languages
- The app is available in **English, Deutsch, Español, Français and Italiano**.
- Every user has a language (Dashboard → Language). It sets the app language and the preselected recipe language; recipes are translated during extraction if the video is in another language.
- New accounts choose their language at registration (preselected from the browser). Existing accounts start with English.
- Dates and error messages follow the user's language.

### Security
- Integration credentials are encrypted at rest (see breaking change 1).
- Stored credentials never appear in API responses or logs.

## 🔧 Improvements and fixes

- Wrong Mealie credentials no longer log you out of JarIt.
- The recipe editor shows "Unsaved changes" correctly after navigating away and back, and never shows or saves another extraction's recipe.
- After a retry, the running time starts again from zero.
- The admin panel uses the shared API client, so its errors are translated too.

## 📦 Operations

- **yt-dlp is no longer updated at container start.** Containers start faster and without network access to PyPI. Instead:
  - every image build includes the newest yt-dlp, and
  - a scheduled workflow rebuilds the backend image of the latest release **every Monday** with the newest yt-dlp and updates the `latest` and minor (`1.2`) tags. Exact tags such as `1.2.0` stay as released.

  Pull regularly to pick these updates up (`docker compose pull && docker compose up -d`, or a tool such as Watchtower).
- The backend image no longer contains test and lint tools.
- The frontend image is built with Node 24 (Node 20 is end-of-life).
- Dependabot opens weekly update pull requests for Python, npm, Docker base images, Docker Compose and GitHub Actions.
- Every pull request runs lint, type checks, tests with at least 80 % coverage, and builds both Docker images.
- `.env` files are no longer copied into Docker images.

## Upgrade checklist

1. Back up your database.
2. Add `JARIT_ENCRYPTION_KEY` to your `.env` (and to the backend's environment in your compose file).
3. Make sure the backend runs as a single uvicorn process.
4. `docker compose pull && docker compose up -d`
5. Check the backend log for the migration message and that it started.
6. Back up the encryption key together with your database backups.
